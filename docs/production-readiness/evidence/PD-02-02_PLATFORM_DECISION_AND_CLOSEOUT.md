## 4. D-15 — Đề xuất và thay đổi nếu được duyệt

Đề xuất **B**, giữ Java 17 và ưu tiên BOM duy trì để giảm override thủ công. A khả thi nếu owner có entitlement bao phủ cả Boot và Cloud. Chọn exact GA và quét lại ngay trước triển khai thay đổi, vì version và advisory có thể đổi.

1. Cập nhật parent ở `pom.xml`, `risk-scoring-service/pom.xml`, `gateway/pom.xml` và Cloud BOM ở Gateway. So sánh effective graphs, bỏ override 2.x/4.1 không còn phù hợp với BOM mới sau khi kiểm từng advisory. Kiểm tên starter/module test, plugin Maven, CI và Java builder/runtime pin. Không đồng bộ POM SPI theo Spring BOM.
2. **Portal/Risk Servlet.** Di chuyển Jackson runtime sang API/BOM được Boot quản lý. Review mapper trong lỗi Security, DTO, Risk admin HTTP client, trace và serialization null/strict fields. Giữ wire JSON dùng với frontend và SPI, không đổi cơ chế JWT/RBAC. Chạy direct read-only/provisioning denial, H2, native MySQL synthetic validate/upgrade và Redis trust state. Kiểm Hibernate mapping, schema guard, Connector/J, Flyway module, compile helpers trong Dockerfile và V5 checksum/classes. Nếu artifact dùng baseline khác cần migration contract test được owner review trước khi chọn.
3. **Gateway WebFlux.** Kiểm starter, route property prefix và filter ordering của Gateway 5. Duy trì trusted socket/CIDR và một canonical XFF. Kiểm Security 7 DSL, JWKS/algorithm/issuer/audience/azp/caller, CORS/OPTIONS, 400/401/403/404/413/429, timeout/pool/backpressure và Observatory deny. Không thay điều kiện cấp quyền để thích nghi API.
4. **Tooling.** CI chạy đủ Portal/Risk/Gateway/SPI/Frontend trên các pin hiện hành. ESLint 9 đã hết duy trì. Đánh giá riêng ESLint 10 với peer plugins và chế độ flat config, không gộp upgrade chỉ để làm sạch số audit. Chạy lại frontend checks và hai build, NGINX loopback, secrets/age và Observatory tests. Chụp dependency diff, SBOM và scan từng artifact ở bước release được phép. [ESLint lifecycle](https://eslint.org/version-support/) · [Evidence PD-02-07](PD-02-07_PUBLIC_DEMO_UI_OBSERVATORY.md)
5. Tách thay đổi BOM, compatibility và packaging thành các diff có thể đảo riêng. Nếu regression hoặc schema mới chưa tương thích, dừng trước runtime và hoàn tác patch ứng viên. Với runtime đã migrate sau phê duyệt riêng, rollback cần artifact N-1 cùng snapshot/config tương thích và rehearsal restore. Baseline EOL chỉ dùng trong vùng private.

## 7. D-16 — Đề xuất và thay đổi nếu được duyệt

Đề xuất **26.8.2** cho candidate Public Demo riêng, chọn digest theo platform tại bước thực thi. Giữ build SPI Java 17 nếu API compiler vẫn cho phép. CI kiểm provider trên JDK 21 tương ứng image khi dựng môi trường được phê duyệt. Công sức ước tính 3–6 ngày kỹ sư sau khi có quyền làm runtime synthetic. Nếu vendor chưa có bản xử lý residual High, đóng từng advisory bằng vendor evidence, feature/reachability proof hoặc phê duyệt ngoại lệ từng mục theo roadmap.

1. Đổi `keycloak.version` ở `keycloak-risk-extension/pom.xml` để đồng bộ provided APIs. Kiểm packaging provider, Jakarta REST và test-only Resteasy. Giữ Admin Client 26.0.12 và SPA adapter 26.2.5 ở nhánh độc lập, điều chỉnh nếu test cho thấy incompatibility.
2. Pin **cả hai stage server** trong `deploy/docker/Dockerfile.keycloak` cùng digest, build optimized image với provider và `keycloak-theme/zerotrust`. So sánh config của `deploy/demo/keycloak-entry.sh`, launcher và `render_ingress.py` với migration guide, gồm hostname, management port, proxy headers, TLS và secret-file mounts. Kiểm provider discovery sau Quarkus augmentation, startup fail-fast khi sai secret/caller, sau đó quét image đã build theo digest.
3. Sau phê duyệt riêng cho runtime, dùng realm, accounts, signing keys, DB/TLS, mail sink và stores synthetic mới trên mạng private. Rehearse import/readback bằng realm fixture hiện có, required actions, cache/session và Keycloak schema trên DB synthetic. Không lấy kết quả kiểm thử Lab làm đối chứng candidate.
4. Rollback candidate bằng provider/image/config cũ trong môi trường cô lập. Nếu Keycloak schema đã thay đổi, dùng DB snapshot trước nâng cùng version cũ. Keycloak hướng dẫn dừng các node khi nâng minor và bản 26.8.2 có thay đổi DCR policy yêu cầu tránh mixed-version nodes. Artifact 26.7.0 chỉ dùng để chẩn đoán private.
